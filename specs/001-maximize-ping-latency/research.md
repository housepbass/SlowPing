# Research and decisions

- Decision: native SVG and native HTML controls. Rationale: small labeled networks, keyboard alternatives, no runtime libraries. Alternative: canvas/Three.js adds dependency and accessibility work without improving this mechanic.
- Decision: protocol-specific `decide(level, routes, deviceId, packet)` returns `{nextHop, reason}`. Rationale: route selection can change without coupling diagram or scoring. Alternative: hardcoding lookup in renderer prevents reuse. A planning research agent reviewed these boundaries; no implementation delegated.
- Decision: request and reply traverse independently, each TTL 8. Decrement at each router before outgoing link, discard at zero. Do not expire immediately on detecting a repeated router. [RFC 1812 §5.2.4](https://www.rfc-editor.org/rfc/rfc1812.html#section-5.2.4), [§5.3.1](https://www.rfc-editor.org/rfc/rfc1812.html#section-5.3.1), [RFC 792 Echo or Echo Reply](https://www.rfc-editor.org/rfc/rfc792.html). Relevant official text checked during specification.
- Decision: fixed symmetric link delays, zero processing/queue delay, logical endpoint attachments, no ARP or interface subnets. This explicitly teaches route/RTT relationships; it does not reproduce a vendor OS.
- Decision: finite prefix/next-hop options and independent path-enumeration oracle. Three topologies have 3/4/5 routers. Level 1 has delays 1,20,30,1 along chain and direct bypass 5: baseline14, request-only maximum59. Level2 chain 2,15,25,20,2 and bypass8: baseline24, reply-only maximum76. Level3 chain3,18,24,28,36,3 and bypass16 with R2–R4 shortcut6: baseline44, maximum224 using longest chain both ways. Extra looping options are legal configurations but fail ping.
- Decision: target is visible, all optima accepted, assistance tracked independently. Alternative hidden optimum obscures whether a learner finished.
- Decision: clear stale feedback after applied edits; an unapplied form does not affect ping. Reset preserves earned completion and assistance, restart clears everything after confirmation.
- Future limits: MPLS-TE requires label/path context. STP, EVPN flooding and storms require protocol state, multiple emitted packets, and bounded event time; IPv4 TTL does not limit Ethernet storms. These are later feature changes, permitted immediately on owner confirmation of MVP.
- No unresolved technical decisions remain for the initial MVP.
